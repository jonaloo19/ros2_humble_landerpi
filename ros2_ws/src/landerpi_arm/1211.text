我理解你的需求：在不改现有抓取 Action 服务的前提下，增加一个离线脚本节点，完成“HOME → 巡航姿态 → 订阅检测结果 → 变换坐标 → 调用 /arm/pick_pose 抓取”流程，同时保留现有 send_pick_goal 的命令行功能，并新增订阅坐标话题的自动抓取入口，预留给后续导航模块调用。

以下是方案设计（本次不改代码，只描述实现步骤与接口）：

### 0. 关键约束与现状
- 抓取 Action：`/arm/pick_pose`，类型 `landerpi_interfaces/action/PickPose`，规划在 `base_footprint` 坐标系。
- 相机：`depth_cam_link`，话题 `/depth_cam/depth_cam` (RGB), `/depth_cam/depth_image` (Depth)。现有检测节点输出 `detection_info`/`positions_with_depth`，已包含像素、深度和可选 3D（相机系）。
- 机械臂姿态：当前抓取服务器强制先回 HOME。你希望启动时先从 HOME 转到“巡航姿态”（观测用），再进行抓取；后续导航模块也会从巡航姿态开始。

### 1. 巡航姿态定义
- 在离线脚本内定义一组“巡航关节值”，例如：
  - `cruise_joints = [joint1_yaw_forward, joint2_up, joint3_fold, joint4_fold, joint5_neutral]`
  - 需你提供或试验一组安全数值（确保相机朝前且不碰地/车体）。示例可从当前 HOME 做微调：`[0, -0.5, 1.0, -0.5, 0]`（需实测）。
- 流程：启动后
  1) 先等待 MoveIt/控制器 ready；
  2) 先回 HOME（保持与现有 server 逻辑一致，防止状态未知）；
  3) 再规划到巡航姿态（关节空间）并停留，开始订阅检测。

### 2. 深度到坐标的转换与接口
- 新增节点（可放 `landerpi_arm/landerpi_arm/color_pick_executor.py`，仅为规划）：
  - 订阅：`/color_detection/detection_info`（优选，含 3D）或 `/color_detection/positions_with_depth`。
  - 若检测消息含 `x_3d,y_3d,z_3d`（相机坐标系），则：
    1) 构造 `geometry_msgs/PointStamped`，frame = `depth_cam_link`；
    2) 用 TF 将点变换到 `base_footprint`；
    3) 生成 `PoseStamped`（位置用变换后的点，姿态留空由 server 设置）。
  - 若无 3D，仅有 (u,v, depth)：
    1) 结合相机内参或 `/depth_cam/rgb/camera_info` 做 pinhole 反投影求相机系 3D；
    2) 同上做 TF。
- 质量/鲁棒性：
  - 对 bbox 中心的深度取多点中值，避免单点噪声；
  - 忽略深度无效的目标；可按颜色优先级/面积排序，取第一个可用目标。

### 3. 调用抓取（复用 send_pick_goal）
- 保留命令行方式：`ros2 run landerpi_arm send_pick_goal --x ... --y ... --z ... --frame base_footprint`。
- 在 color_pick_executor 中，增加“自动模式”：收到有效目标后，直接调用 PickPose Action：
  - 目标 frame：`base_footprint`；
  - 位置：上一步 TF 后的 3D 点；
  - `object_id`: 可填颜色名或空。
- 抓取服务器会：
  1) 回 HOME（不可改的现有逻辑）；
  2) safe_approach(+0.25)、pregrasp(+0.12)、descend(-0.10)、lift(+0.15) 以及末端朝下姿态。

### 4. 面向导航的预留接口
- 在 color_pick_executor 中提供两种触发方式：
  1) 自动监听检测，发现可抓目标立即调用（用于静态测试/示例）；
  2) 服务或 action 触发（例如 `/color_pick_executor/pick_first`），导航模块在到位后调用，避免边走边抓的误触发。
- 入口参数：目标颜色（可选）、是否只抓最近/最大面积的一个。
- 输出：结果 success/fail，错误码复用抓取 Action。

### 5. 对你提出问题的回应
- 问题 1/2：导航时应使用巡航姿态，便于观测；现有抓取流程会先回 HOME，再去抓。如果不想回 HOME，需要改 grasp_action_server 逻辑（本次不改）。在当前逻辑下，巡航仅用于观测，真正抓取前会回 HOME 再执行。
- 问题 3：未知物体大小时，按 bbox 中心 + 多点中值深度 → 反投影 → TF → 末端垂直抓取即可，大多数小方块可抓到质心附近。可再加滤波/排序。
- 问题 4：`landerpi_arm` 下不建议删核心文件；新增 color_pick_executor.py（独立脚本）来做订阅/变换/调用。send_pick_goal 保留 CLI，同时扩展为可被 executor 以函数或内部客户端方式调用。
